📋 Project Overview

What Does This Code Do?

This Pygame application simulates 10 animated colored squares that move around a canvas with realistic physics, survival mechanics, and social behaviors. Each square has its own lifespan and can "flee" from larger squares that approach too closely.

Core Concept

The program demonstrates several important game development concepts in one cohesive example:

  • Entity-Component Behavior: Each square is an independent entity with state and behavior
  • Physics Simulation: Velocity-based movement with time-independent updates (delta time)
  • Perception & AI: Squares "sense" nearby larger threats and respond intelligently
  • Object Lifecycle: Birth (random spawn), aging, death (lifespan expiry), and rebirth (replacement)
  • Real-time Rendering: Efficient frame-based drawing with collision response

⚙️ Game Mechanics Deep Dive

1. Delta Time Physics

Problem: If you use `x += vx` per-frame, speed changes with FPS.
Solution: `x += vx * delta_time * BASELINE_FPS`
Result: Movement is consistent across 30 FPS, 60 FPS, 120 FPS.

2. Size → Speed Inverse Relationship

size_ratio = (size - MIN) / (MAX - MIN) # 0 to 1
max_speed = MAX_SPEED - size_ratio * (MAX_SPEED - MIN_SPEED)
# Bigger squares = lower max_speed (slower apex predators)

This creates a naturally emergent predator-prey dynamic without explicit "combat" rules.

3. Fleeing Algorithm (3-Step)

Step 1: Detect Threats

Scan all squares. Only consider those larger AND within FLEE_RADIUS (150px).

Step 2: Compute Flee Direction

For each threat, create unit vector pointing AWAY. Pick random direction if distance=0. Track closest threat.

Step 3: Apply Impulse

strength = (threat_size - self.size) × (proximity) × FLEE_STRENGTH. Add to velocity, clamp speed.

4. Jitter (Velocity Rotation)

Random small rotations of the velocity vector create organic, unpredictable movement. Uses 2D rotation matrix to preserve speed:

vx' = vx*cos(θ) - vy*sin(θ)
vy' = vx*sin(θ) + vy*cos(θ)
# Speed magnitude is preserved, only direction changes

5. Wall Collision & Bouncing

When hitting a wall, the velocity component is reversed (elastic collision). Position is also clamped to prevent escape:

if x ≤ 0 and vx < 0: vx = -vx # bounce
x = max(0, min(x, WINDOW_WIDTH - size)) # clamp

6. Lifespan & Rebirth

Each square has random lifespan (30–180 sec). When age ≥ lifespan, it dies and is replaced. Total count stays at 10 always.

📖 Methods & API Reference

Square.__init__(x, y, size)

Purpose: Initialize a new square with random movement, speed (based on size), lifespan, and color.

Key Attributes: x, y, size, age=0, lifespan, vx, vy, max_speed, color

Lifespan Range: 30–180 seconds (random.uniform)

Square.snapshot()

Returns: SquareSnapshot (immutable dataclass)

Purpose: Capture current state (owner, x, y, size) as immutable snapshot. Used to ensure all fleeing calculations in a frame use the same data.

Square.update(all_squares, delta_time)

Purpose: Main update method. Calls update_age, apply_fleeing, apply_jitter, clamp_speed, then moves by velocity and bounces off walls.

Parameters: all_squares (list of snapshots), delta_time (seconds)

Modifies: age, vx/vy, x/y

Square.apply_fleeing(all_squares, delta_time)

Purpose: Detect larger squares within FLEE_RADIUS and compute flee vector based on closest threat.

Logic: Strength ∝ size_diff × proximity × FLEE_STRENGTH. Clamps speed after applying.

Square.apply_jitter(delta_time)

Purpose: Apply jitter by rotating velocity if random chance succeeds and JITTER_ENABLED=True.

Square.rotate_velocity(angle_radians)

Purpose: Use 2D rotation matrix to rotate (vx, vy) by angle while preserving speed magnitude.

Square.draw(surface)

Purpose: Render square on pygame.Surface at current position, size, and color.

handle_lifespan_rebirth(squares)

Purpose: Remove dead squares (is_dead()=True) and spawn replacements to maintain pool at NUM_SQUARES.

main()

Purpose: Initialize game state and run the main frame loop. Handles events, updates, rendering, FPS capping.

🎯 Code Patterns & Best Practices

✅ Good Patterns (3)

1. Type Hints Throughout

Every function parameter and return value has explicit type: `def update(self, all_squares: list[SquareSnapshot], delta_time: float) → None`. Clarity, IDE support, error prevention.

2. Snapshot Pattern for Order Independence

Create immutable snapshots before updates. All fleeing calculations use frozen data, not live. Prevents subtle update-order bugs.

3. Delta Time for Frame Independence

Use `position += velocity * delta_time` not `position += velocity`. Speed is consistent across all frame rates.

⚠️ Areas for Improvement (2)

1. Magic Numbers

Values like FLEE_STRENGTH=0.25, FLEE_RADIUS=150 are helpful constants, but some magic numbers still exist (0.0001 epsilon guard). Extract to named constants for clarity.

2. Complex apply_fleeing() Method

Long (~45 lines) with nested logic. Could refactor into smaller helpers: _find_closest_threat(), _compute_flee_direction(), _apply_impulse(). Each piece testable independently.
